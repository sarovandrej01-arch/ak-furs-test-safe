# Методы решения без результатов исходного набора

- Q1: номер заказа проверяется целиком с учётом латинского/кириллического
  префикса; ключ строки состоит из номера заказа и позиции. Побеждает
  последняя выгрузка, при равенстве — последняя запись источника.
- Q2: направление берётся из типа операции, связь — из явной ссылки на
  существующий заказ. Один номер счёта не доказывает связь. Денежные
  расчёты используют Decimal. Достаточно одной оплаченной строки заказа.
- Q3: цепочки переименований приводятся к конечному коду; циклы запрещены.
  Прайс выбирается на дату создания по включительным границам. Фиксированная
  скидка относится ко всей строке. Равенство минимуму не является нарушением.
- Q4: сравниваются первые события менеджера в порядке исходных сообщений.
  Реплики клиента и информация о расположении салона не заменяют эти события.
  Приглашение без объявления цены считается нарушением. Одновременные события
  в одной реплике отмечаются для проверки, строгий порядок не предполагается.

## Исправления, выявленные при работе с AI-агентом

Исходный вариант слишком широко исключал сообщения с упоминанием доставки,
не распознавал группировку суммы пробелами без валюты и пропускал отрицание
в одном из вариантов ожидания клиента. Исправлены общие правила контекста
цены и области действия отрицания; добавлены отдельные и диалоговые тесты.
История изменения кода сохраняет эти этапы. Это описание не является
экспортом диалога с агентом и не выдаётся за такое свидетельство.

Классификатор основан на правилах и не гарантирует понимание любых новых
оборотов. Новые спорные случаи следует проверять и покрывать контрпримерами.
